# Cluster tab → ComfyUI-style wiring editor

## Context

Replace the `/cluster` floor (hand-drawn SVG in `ui/src/tabs/cluster/`, 3k lines of `layout.ts`) with a React Flow (`@xyflow/react` v12) node-graph editor. Blocks: entry endpoints, machines (live telemetry), deployments, **provider models drawn as their own blocks exactly like deployments**, served-name **route** blocks (the load balancer: policy, operator-ordered failover chain, operator-set weights), providers, orgs, API keys, **rate-limit** blocks, droppable **model** blocks that wire to machines and launch, and an **MTP** block drawn as a connection on every local model/deployment whose checkpoint carries a multi-token-prediction module — a switch that enables speculative decoding on launch. The operator drags wires; the server validates the whole draft through a new `POST /api/wiring {dry_run}` on every change; Save applies the batch in order and shows each result verbatim. Request flow stays visible: the floor's particle layer is ported onto the wires. Three phases, each landing green before the next.

What a wire means (verified; nothing else is operator-writable today, and Phase 1 adds the three marked **new**):

| Block / wire | Server state | Call |
|---|---|---|
| route block policy | per-served-name override, 7-value `RoutingPolicy` or auto | `PUT /api/routing/{name}`, `DELETE` (auto) — persisted in `routing.json` (**new**) |
| route block failover chain | **new** `failover_order: [target_id]`, honoured by `failover` (today `_stable_order`: locals first, then by id) | same PUT |
| route block weights | **new** `weights: {target_id: share}`, honoured by `weighted_capacity` in place of computed weights | same PUT |
| provider model block → route | `enabled_models` + `aliases[upstream]=served_name` | `PATCH /api/providers/{id}` |
| provider block fields | `enabled`, `priority` | same PATCH |
| org block | `routing_policy`, `allowed_models` (wires to routes), `limits` (limit blocks) | `PATCH /api/orgs/{id}` |
| key block | `routing_policy`, `allowed_models`, `cloud_fallback_local_model`, `limits` | `PATCH /api/keys/{id}` |
| limit block | entries of a key's/org's `limits` dict; model-scoped entries `model:<served>:<rpm|tpm|tokens_cycle|usd_cycle>`. A limit wired straight into a route is refused — no global per-model cap exists | folded into the two PATCHes |
| model block → machines | `node_ids` of a launch | `POST /api/plan` then `POST /api/deployments` |
| MTP → model block | **new** `speculative_tokens` on the launch; fit charges the MTP parameters back | `POST /api/plan`/`/api/deployments` |
| MTP → deployment | solid when the deployment was launched with `speculative_tokens > 0`; acceptance rate from `/api/usage` `spec_acceptance_rate` | read-only |
| all of the above except launches | validated and applied as one batch | **new** `POST /api/wiring` |
| deployment → machine, deployment → route, provider → provider model, key → org, route → entry | fixed facts, drawn, not editable | — |
