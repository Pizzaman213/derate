# cluster

The machine floor: one plate per node in `/api/topology`, running or not, with
the request flow drawn through it. Where a machine sits is a pure function of
the node set plus the operator's own arrangement, never of a simulation — the
same cluster at the same viewport draws identically every time, because a
machine that moves between refreshes is a machine you cannot learn the position
of.

`layout.ts` is the largest file in `ui/src` at 3012 lines and
`ClusterGraph.tsx` is its largest component, and the two are split on one line.
`layout.ts` decides where everything goes and touches no DOM; `ClusterGraph.tsx`
is the only thing that puts any of it on screen. That split is what lets four
plain node scripts check the floor's geometry, its motion, its particles and its
launch stepper without a browser.

## `layout.ts`

The whole drawing as arithmetic. `layoutCluster(input)` returns a
`ClusterLayout` — `cards`, `edges`, `bands`, `conns`, `entries`, `exits`,
`provider`, `slots`, `paths` and an `ink` box — and nothing in it is a
measurement taken from the DOM. Every string width is arithmetic
(`textWidth`: IBM Plex Mono's advance is 0.6em), so the checker gets the same
answer the browser does.

The structure replaced a diagram that iterated deployments rather than nodes,
so a machine hosting nothing was never drawn, a machine serving two deployments
was drawn twice, and the only links on the canvas were between adjacent nodes
inside one deployment row. On a live two-node cluster with one unmeasured link
that rendered one card and zero links.

**Channel grammar, one meaning each.** Width is measured all-reduce bandwidth
and nothing else; a dash means never measured and nothing else; opacity means
deprioritized; colour means something is wrong, and a healthy link is a
hairline. So an unmeasured link is a fixed hairline carrying no figure, never a
thin line implying a small number nobody has.

Everything is in AUTHORED units and the viewBox divides by `GSCALE` (12/9), so
9 authored px renders at the 12px floor the rest of the panel keeps and no
constant has to move when the type scale does. `CARD` is the three plate sizes,
constant per tier and never divided by the node count — the old flow diagram
sized boxes as `(TW - (k-1)*GAP)/k`, which goes negative at five in a row and
silently erases them.

### The floor is dealt, not simulated

`reconcileOrder(nodes, order)` produces the arrangement: the stored permutation
filtered to who is present, then anyone who joined since, appended in
`defaultArrangement` order — coordinator first, then lexicographic by node id.
The floor always rests at the `chip` tier, whatever the node count — selecting
a plate still promotes it to `compact` in place, on the ring as well as the
grid, showing power, temperature and (under weighted routing) this machine's
traffic share; `full` (utilization, memory, hardware spec, a renamed machine's
identity line) is reachable only from the roster sidebar and the node sheet
now, not from the floor itself. `RING_ABOVE` (12) is where a grid stops being
legible and the floor becomes a ring. A ring's routes are chords, because
squaring off the line between two centres would draw two sides of a box across
the inside of a circle.

`moveToSlot` is what alt+arrow writes. A pointer drag writes an offset instead,
applied in one pass after the slots are dealt and before anything is measured
off a plate — so links, band spans, leads, flight paths and the ink box all read
the displaced geometry for free. `slots` is deliberately not displaced: it stays
the home grid a cleared offset returns to.

`OFFSET_LIMIT` (4000 authored units) bounds a stored placement. It is not a
fence anybody drags into — a pointer drag is 1:1 with a pointer inside the
window — but a corrupt or hand-edited value must not fling one plate far enough
to shrink the rest of the floor to nothing.

### Only the pairs worth drawing

`/api/topology` returns a complete graph: 6 edges at four machines, 66 at
twelve, of which realistically one or two carry a figure. Drawing all 66 is a
hairball that hides the one that matters. A pair is drawn when it is measured,
when a deployment spans it, at four machines or fewer, or when either end is
selected; the rest are counted into `suppressedPairs` and the rail says so.

`edgeMeasured(edge)` is the one definition of "measured" any link, chip or tally
may use: the wire's own flag AND an actual `all_reduce_gbps` to show for it. An
edge claiming `measured: true` with no figure has nothing to draw and must read
exactly like one never probed — `SelectionRail.tsx` and
`inspectors/node/Interconnect.tsx` import it so the count beside the chips can
never disagree with the chips.

### Which provider models belong on the floor

`groupRemotes(remotes, localNames)` is the rule, and it reads the topology
payload and nothing else so it stays pure. An OpenRouter key with no allowlist
is several hundred remote rows; a band each would bury the machines under a
catalogue nobody deployed. A row earns a place only when somebody here did
something to it: `backup` (a local deployment already serves that name, so the
provider rides on that band rather than getting one), `hosted` (the provider IS
a node on this roster), or `named` — an alias is set, or the providers behind it
serve `SHORTLIST_MAX` (8) names or fewer between them, which is what makes a
model allowlist show up here. Everything else is `catalog`: counted on the
provider bus and not drawn. `layout.check.mjs` holds the case directly — forty
catalogue models draw one band, not forty-one.

### Two more exported rules

`endpointGroups(bands)` groups bands by endpoint family in `MODALITY_ORDER`,
omitting families with no band, and each group gets its own entry plate carrying
its own route — `ENTRY_LABELS` mirrors `ENDPOINT_FOR_MODALITY`. One plate
reading `POST /v1/chat/completions` in front of both a speech band and a chat
one is not a simplification of the routing, it is a drawing of routing that does
not exist. `separate(plates, h)` then pushes overlapping plates apart in place:
two families whose bands interleave want the same middle, and two routes drawn
in one rectangle read as a rendering fault. The connectors are not moved, so a
lead still leaves the y its group was centred on.

`runners(deployments)` filters `/api/deployments` down to what still holds a
machine, using `TERMINAL` from `models/rows.ts` rather than a second list
spelled the same way. The ledger keeps every attempt: three failed tries at one
model are three rows with the same served name and node, and the band has no
vocabulary for "over" — so they drew as three identical runners, each claiming a
machine running none of them. Live duplicates are still two bands; the ledger
was the duplication, not the cluster.

## `ClusterGraph.tsx`

The only consumer of the geometry, and the only file here that touches the DOM
directly. `ClusterGraphHandle` exposes one method, `reset()`, which
`GraphToolbar` calls.

**The resting view is a fit, not the identity.** The viewBox is the element's
own box, so at k=1 a two-machine drawing occupies a fifth of it. The fit scales
`layout.ink` up until it meets the viewBox on whichever axis binds first and
centres it; a drawing bigger than the floor scales down by the same expression,
so the dense case needs no branch. `ZOOM_MIN` (0.4) and `ZOOM_MAX` (4) are
therefore RELATIVE to that fit — absolute limits would be useless, since a fit
that landed at 4 would leave no room to zoom in at all.

**The frame chases the machines, not the bands.** The fit is recomputed on
every layout, but it is only APPLIED when the machines lay out differently or
the element resizes (`frameKey`), plus once when the deployments resource
first answers, so a page opened mid-launch frames the launch band it is about
to draw. It deliberately does not re-apply when the band stack breathes: a
launch stepper is a 103-unit band that appears at PLANNED, vanishes on a
crash, reappears on the relaunch and shrinks to `BAND_H` at READY, and
re-fitting on each of those slid and rescaled every plate on screen — the
machine somebody was watching moved in step with the download under it, which
is the one thing the layout is engineered never to do. A band taller than the
held frame hangs below its bottom edge until the launch settles; the pan still
reaches it and `Reset view` re-frames on demand. `offsetX` drift from a band
growing for its words is compensated in the view transform for the same
reason, panned or not, so the drawing never slides sideways under anybody.

Pan and zoom are a ref-written `transform` attribute, never React state. Live
telemetry is the deliberate exception: the meter fill and the state border are
part of the plate rather than an overlay on it, so the plates are one live
component re-rendering at 1 Hz.

**The browser's `dblclick` never reaches a plate.** The drag handler takes
pointer capture on the SVG the moment a plate is pressed, and capture retargets
the compatibility mouse events — `click` and `dblclick` included — to the
capture element. So the press path pairs the two presses itself inside
`DOUBLE_MS` (400ms), and `DRAG_SLOP` (5 CLIENT pixels) is what a pointer must
travel before a press becomes a drag rather than a click. Client pixels, not
scene units: scene distance is client distance divided by the zoom, so a
scene-unit slop shrank to a couple of real pixels at a zoomed-out fit and
click jitter started drags nobody meant. Without it, selecting a machine
nudges it.

**A drag ends even when its `pointerup` never arrives.** Capture is supposed
to guarantee delivery, but Chrome can drop the release when the pressed
element was unmounted mid-gesture — and this floor unmounts the pressed
element routinely: the ghost re-parent when slop is exceeded, every poll
re-render, a crash-looping launch whose band dies under the pointer. A band
stuck in that state followed the bare cursor forever. Three backstops close
it: a `pointermove` with no buttons down ends the gesture (drop if it had
moved, dissolve if it had not — synthesising a click seconds late would
select something nobody asked for), `lostpointercapture` is treated as
`pointercancel`, and a dragged id that vanishes from the layout clears the
drag state with it.

Nothing snaps and nothing is refused on a drop. A plate can land on a link or on
another plate: the floor is a drawing of a rack somebody is looking at, and
where they want a machine is not this component's vote. Two things follow it,
because they are drawings of it rather than decoration near it — its links
re-aim, and its band's bar re-spans, both worked out in `layout.ts` from the
final geometry.

Alt+arrow on a focused machine reorders it and is guarded on
`layout.arrangement.includes(focused)`: the provider bus carries `.machine` too
but was never dealt a slot, and `moveToSlot` on an id that was never in the
array would insert it and corrupt the persisted order for every real node.
`bandTokensPerSec` is exported so the readout on a band and the rate its
out-stream flies at come from one expression; a remote band is summed from its
own targets off the 1 Hz frame rather than joined to `/api/topology`'s honest
but 5s-old copy, because a band ticking five times slower than the one above it
reads as a fault in the drawing.

## `SelectionRail.tsx`

The rail under the floor. A selected link gets `LinkRail` or
`UnmeasuredLinkRail`; nothing selected gets `DefaultRail`, which lists every
pair as a chip with its figure or `never measured` and states the tally. A
machine is deliberately not a rail state — pressing a plate only lights it, and
its readouts live in the node sheet a double-click opens. One detail surface,
one way into it.

**Reachability is a separate, cheaper question from bandwidth, and is offered
on unmeasured pairs too.** A measurement saturates the fabric for about a
minute to say how fast; `ReachPanel` costs four health checks and says whether
anything gets through at all — a machine that does not answer is a finding you
want before you spend that minute. Every leg is listed rather than reduced to
one verdict, because a one-way failure (a worker that can dial the coordinator
but not be dialled back) is the common real fault, and a merged "not connected"
sends an operator to the machine that is demonstrably fine. Three outcomes per
leg, not two: a direction nobody could test is not a failure, and a failed one
carries no millisecond figure, because `0 ms` beside "unreachable" reads as a
fast link. A leg whose `answered_as` is not its target says so — reaching
something at an address is not reaching the machine you meant.

## `particles.ts`

An imperative rAF layer written as DOM attribute writes outside the render tree,
so a flight survives a pan or a zoom and costs nothing in reconciliation.
`spawnParticle` draws one block as a `stroke-dasharray`/`stroke-dashoffset`
segment of `pathsRender[key]` -- the SAME rendered, filleted path string the
wire itself strokes, the technique the header logo's own pulse uses -- and
slides it along by `getTotalLength()`, then removes it. Walking the rendered
path rather than interpolating the unfilleted `pts` vertices is what keeps the
block on the wire through a corner instead of cutting across it.
`useParticleField` is the mount-scoped top-up loop on `TOPUP_MS` (200ms), fully
suppressed under `prefers-reduced-motion`.

**One block means one thing, and the two directions mean two different things.**
Inbound, the POPULATION is the measurement: N blocks on a path is N requests in
flight on that target, read off `queue_depth` at 1 Hz or `RouteTarget.outstanding`
on the 5s routing poll, whichever is fresher — and the slower one takes over the
moment the stream goes stale rather than freezing on a count that stopped
arriving. Outbound, the RATE is the measurement and the population means
nothing: blocks leave at a compressed, capped image of measured tok/s, so nobody
can count blocks and arrive at a token figure. Out-blocks therefore fly at a
constant `STREAM_FLIGHT_MS` (900) — spacing carries the rate, and encoding one
number in two channels makes neither readable.

What is not ported from the mockup is its fiction: flights on a fixed 380ms
metronome, each drawing its path from a client-side weighted coin toss.
`particles.check.mjs` exists so a regression back to that fails something.

The limits are stated rather than fudged. A request beginning and ending between
two samples was never visible and gets no block. `flightMs` clamps a target's
measured mean duration into `[MIN_FLIGHT_MS, MAX_FLIGHT_MS]` (700–8000), because
a 40ms flight is a flicker and a 90s one reads as a stall; past the clamp the
speed stops tracking the measurement but its presence does not.
`streamCredit`'s epsilon is not a fudge either — a rate of exactly one block per
N ticks accumulates N floats summing to 0.9999999999999999, so the block slipped
a whole tick every cycle and the slowest bands emitted at nine tenths of what
was measured.

**`streamTone` paints a live animation with a historical ratio, knowingly.**
`GET /api/history/requests` is the only place that records whether a request
asked for `stream: true`; the 1 Hz frame carries no such flag and `/api/routing`
does not split `outstanding` by it. So a name that streamed all afternoon and is
being batch-hammered right now keeps the streamed colour until the window rolls.
Presence and rate are live, colour is historical, the legend names the window,
and a ratio nobody has rows for paints the same "no reading" grey the empty
meter track uses. `streamBlockWidth` carries the same distinction in shape (6
units streamed, 11 buffered) so it survives a colour-blind reader and a
greyscale screenshot.

## `LoadingBand.tsx`

A deployment that has not arrived yet, drawn on the band that already names it.
Before this the band drew a throughput readout and `fmt` rendered the missing
figure as an em dash — honest, and silent about why. The furniture is the setup
screen's launch plate re-drawn in SVG: same four phases, same three marks, same
sweeping bar, so a launch watched during first run and the same launch watched
on the floor are visibly one event.

`BandSweep` claims no position. There are two rects, one per motion preference,
because the still form is a different shape and not the moving one held: a
40%-wide highlight parked at the left edge would read as 40% done, which is the
one thing this bar must never say.

`BandLaunchLayer` is one component for every loading band rather than one per
band, because it owns the two things that must not be duplicated — the
`/api/activity` poll (`useResource` starts an interval per call site) and the
one-second clock — and because a two-second poll threaded through
`ClusterGraph` as a prop would rebuild every plate, edge and particle host with
it. The group is `pointer-events: none`: the words sit on a band that is a
button, and a click landing on a phase label would silently stop selecting the
deployment.

## `loading.ts`

The stepper as data, so `loading.check.mjs` can pin every rule in it.
`launchView(dep, launch, downloads, now)` returns `steps`, `elapsed` and
`error`; `now` is passed in rather than read, so the verifier can hold time
still. `PHASE_ORDER` is `preparing → downloading → loading → serving`, and
exactly one step is `now` until the deployment is serving, at which point every
step is `done` — a stepper with two current steps says nothing, one with none
has stalled.

**It will not invent a step the wire cannot see.** The setup screen tells
download from GPU-load by polling `/api/storage` every two seconds and watching
the model cache grow; the floor cannot, because that endpoint fans out to every
node and walks a directory on each, which is why it is polled at thirty seconds
— and a phase split made from a thirty-second sample is a guess wearing a tick
mark. So `launching` holds at "Downloading weights", and "Loading onto the GPU"
is ticked only in retrospect. A real provider pull, reporting genuine bytes
against a genuine total, advances it, because then there is something to advance
on. `pullFor` matches on `model_id` and never `served_name`: a served name is an
alias chosen here and the puller only ever saw the model. `elapsed` is null
rather than zero when there is no launch row — null is not zero, and `0:00`
claims it started this second.

## `order.ts`

The arrangement in localStorage under `derate.cluster.order.<clusterId>`, one
record because `order` and `offsets` are one preference and `Reset layout` has
to clear both at once. `order` is a permutation of node ids that KEEPS departed
ids, so a machine that leaves and rejoins returns to the slot somebody put it in;
`layout.ts` filters them when it places.

**`offsets` are DISPLACEMENTS, never absolute coordinates, and that is what
makes free placement storable at all.** This file used to refuse to store one,
on the grounds that free x/y positions stop meaning anything the moment the
viewport resizes or the cluster crosses a density tier. True of an absolute
position and false of a displacement — an offset travels with the slot through
both, so a floor arranged to match the rack still matches it on a narrower
window. What it does not survive is the machine set changing shape underneath
it, and `Reset layout` is the honest way out.

`readArrangement` never throws: private mode, a disabled store, a hand-edited
value and a record from a future `VERSION` all mean "no arrangement, use the
default". `cleanOffsets` drops `{x: 0, y: 0}` on the way in and out, because a
stored zero would make `isArranged` claim an arrangement and light the Reset
button for a floor that has none. `MAX_IDS` is 64.

## `motion.ts`

The floor part way between two layouts, and nothing about the destination:
`layoutCluster` still decides where every plate ends up. What was missing was
the journey — the floor re-laid out on a 5s poll and on every selection, and a
plate that grew in place teleported every row below it.

Two rules hold it up. **A plate is moved by transform, never by re-issuing its
coordinates**: a plate is a dozen absolutely-placed primitives and there is no
useful way to transition a dozen sibling `x` attributes, so `shifts()` renders
it where it has arrived and pushes it back to where it started, and the push is
what animates away. A plate that did not move gets no transform at all rather
than one of zero. **A wire whose shape changed snaps, never morphs**:
`sameShape` requires the same corner count and every run pointing the same way
in both, and `lerpRoute` returns `null` otherwise, because interpolating a
bracket into a hop draws a diagonal halfway through and a slant is the one thing
the router exists to keep off this floor. Both ends of a tween are exact,
vertex for vertex. `ease` solves the plates' own CSS `cubic-bezier(0.2, 0.7,
0.3, 1)` by twenty bisections so a wire tweened in JavaScript arrives with them
instead of racing them.

## `providerLogo.ts`

A provider's mark on the bus, served through `apiUrl` at
`/api/providers/<id>/logo`. **Deliberately none of `tabs/models/owner.ts`'s
machinery**: that module fetches HuggingFace avatars for several hundred cards
from an unauthenticated, rate-limited third party, which is what its LRU-256,
six-way concurrency gate, 10s abort and doubling backoff are all for. Here there
are one to three providers on one bus, the URL is our own coordinator, and
`control_plane/providers/logos.py` already does the caching, the backoff and the
negative caching — repeating any of it would be two caches disagreeing about one
picture.

The exports are `providerLogoUrl`, `providerLogoMissing`,
`markProviderLogoMissing`, `subscribeProviderLogos` and `providerMonogram` --
which returns one uppercase letter and draws nothing. The fallback is solved by
paint order, not by a loading state: a failed `<image>` in SVG renders as
nothing, so `ClusterGraph.tsx` paints the monogram tile ALWAYS and puts the
`providerLogoUrl` mark on top of it. No flicker, no blank frame, and a
coordinator too old to have the route renders exactly what a vendor with no
favicon renders. `markProviderLogoMissing` notifies every
`subscribeProviderLogos` listener so the drawing repaints once instead of every
row re-requesting on each 5s poll.

## `GraphToolbar.tsx`

The one line of chrome above the graph: the drag/pan/zoom hint, the zoom
percentage, `Reset view`, and `Reset layout` only when `rearranged` — a control
that does nothing is worse than no control. The percentage is written straight
into `zoomLabelRef` by `ClusterGraph` on every pan and zoom, never React state,
so this component does not re-render while somebody is scrolling. There is no
separate "fit" control because the resting view is the fit and every machine is
already framed at 100%.

## `layout.check.mjs`

The geometry verifier, and by line count the largest thing checking anything in
the UI. It bundles `layout.ts` with the esbuild already inside vite — node's ESM
resolver will not take the extensionless `../../format` specifier — and then
asserts against the returned object.

What it covers: every density tier and the ring boundary (`build(12).kind ===
'grid'`, `build(13).kind === 'ring'`), selection revealing links — a selected
machine's pairs AND a selected link itself reach the canvas on a floor dense
enough to suppress the mesh — the arrangement rules (a stale order places
every present node and duplicates nobody; departed ids place nothing; a NaN
offset is no offset and an absurd one is bounded, not obeyed — for bands and
the provider bus too, since a NaN reaching any box blanks the whole floor),
the router (two facing plates get a bracket sitting on the meter band, a hop
stays inside the reserved headroom, the ink box encloses every route and
caption so the fit cannot crop one, crossings punch a hole rather than cutting
a wire short, a corner too short to round is left mitred), band spans and
contiguity, the label/throughput gutter that `Qwen2.5-0.5B-Instruct` surfaced,
flight keys (`no ordinal flight keys survive`), and the remote rule — forty
catalogue models draw no band of their own and are counted on the bus instead,
two providers answering for one name is a merge rather than two bands.

It also writes `ui/layout-preview.svg`: the floor at 1, 2, 3, 4, 6, 9, 12 and 16
machines, stacked and rendered at `GSCALE`, so the density tiers can be
eyeballed with no cluster and no browser. That preview is now the only way to
see a shape the live cluster is not currently in.

## `loading.check.mjs`

Pins the stepper. It bundles `loading.ts`, and separately bundles `layout.ts`
for the band's geometry constants, so the drawing checks measure against what
the floor actually reserved rather than numbers retyped here — the exact drift
that puts a phase row through the bar above it. Then it bundles
`LoadingBand.tsx` against `react/jsx-runtime` and renders it, so the assertions
run on drawn output: four phase rows on four baselines, only the current step
gets the waiting dots, the clock sits where the throughput readout would be, and
`nothing on a loading band is a percentage`. `planned is on the first step`,
`launching with nothing reporting holds at Downloading weights`, `a finished
pull is the one thing that advances it to the GPU load`, and `a coordinator
clock ahead of this browser never draws a negative age`.

## `particles.check.mjs`

Pins what gets drawn and what does not. `spawnParticle` is exercised against a
fake layer — one block per flight, starting at the head of its path, half way
along at half the span, removed at the end, `onDone` firing exactly once so the
tally can drop. `flightMs` is checked at its edges: zero is nobody measuring
rather than an instant request, and negative and NaN are not durations.
`collapseFlows` is checked to drop a flow whose path this layout did not draw
rather than redirect it — a request on an undrawn target is better shown nowhere
than on the wrong machine. `targetFlows` is checked to prefer a live
`queue_depth`, fall back to `outstanding` when the frame is stale, and never
read a deployment frame for a remote target. `useParticleField` itself needs a
React tree and is not exercised; its two decisions are `collapseFlows` and
`flightMs`, which are.

## `motion.check.mjs`

Small, and pointed at the two rules a typechecker cannot see. The ends are
exact — `t=0` is the route it is leaving and `t=1` the route it is arriving at,
vertex for vertex, so a tween cannot leave a wire a fraction of a unit off the
geometry `layoutCluster` decided and have the next poll snap it the rest of the
way. And a shape change is a snap: a route that lost a corner or a run that
changed axis returns `null` from `lerpRoute` rather than a diagonal. It also
pins that a machine which has just joined is not slid in from somewhere, that
skipping the tween lands in the same place as finishing it, and that `ease`
clamps outside `[0, 1]`.

## `loading-preview.svg`

Generated output, written by `loading.check.mjs` and listed in `ui/.gitignore`
as `src/tabs/cluster/loading-preview.svg`. It is the loading band drawn at real
size so it can be looked at without a cluster in a launching state. One line
with no trailing newline, which is why `wc -l` reports 0 for a 2.2 KB file.
`layout-preview.svg` is its sibling and lands in `ui/`, not here.

## The seam with the rest of the UI

`tabs/ClusterTab.tsx` is the composition point: it owns the arrangement
(`readArrangement`, `writeArrangement`, `clearArrangement`, `isArranged`,
`NO_ARRANGEMENT` from `order.ts`), holds the `ClusterGraphHandle` ref, and wires
`ClusterGraph`, `GraphToolbar` and `SelectionRail` together.

`layout.ts` is imported by seven files outside this folder, and six of those
take exactly one function:

```ts
import { runners } from '../cluster/layout'     // what is still holding a machine
import { edgeMeasured } from '../../tabs/cluster/layout'
```

- **`runners`** — `inspectors/node/NodeInspector.tsx`, `shell/Sheet.tsx`,
  `sidebar/PlanSection.tsx`, `tabs/dashboard/AggregateRow.tsx`,
  `tabs/dashboard/DeploymentsStrip.tsx`. Every screen that counts what is
  running counts it the same way, so the floor and the dashboard cannot
  disagree about whether a model is up.
- **`edgeMeasured`** — `inspectors/node/Interconnect.tsx`. Same definition of
  "measured" in the sheet as on the canvas.
- **`Point`** — `tabs/ClusterTab.tsx`, for the offsets it persists.

Inbound, the folder leans on `state/selection` for what is selected,
`state/metrics` for the 1 Hz frame, `state/resources` for `/api/activity` and
the request mix, `state/names` for `nodeName`/`nodeSubtitle`, and
`models/rows.ts` for `TERMINAL`.

None of the four verifiers carries a `// requires:` line, which under
`ui/check.mjs` means hermetic — they need the checkout and nothing else, and
they run in `npm run check` on any machine.

## Things that look like details and are not

**Zoom is relative to the fit, not absolute.** `ZOOM_MIN` 0.4 and `ZOOM_MAX` 4
multiply the framing that fills the floor. A two-machine cluster and a
sixteen-machine one both rest at 100%, and both have the same range either side
of it.

**A band's width is not its name's width, and the throughput readout wins.**
A band is as wide as the machines it occupies. `THROUGHPUT_GUTTER` (6 × 7.8 +
11) is reserved from a template rather than measured from the figure on screen,
because that number changes every second off the 1 Hz frame and a clip tracking
it would make the served name's last character flicker once a second.
`bandLabelWidth` then never takes more than half the band, because a
measurement nobody can attribute is worth less than a name with no measurement.

**Every box is sized from the text it draws.** `spark-4d38` and
`Qwen2.5-0.5B-Instruct` need 197 units between them and a full-tier plate is
138, so the plate drew the machine's name through the name of the model it was
serving. The drawing is fitted into the viewBox, so a box that grows costs a
little scale and never a clipped glyph.

**Plate width is floor-wide or nothing.** A row is as tall as its tallest
plate and as wide as its widest, so letting only the long-named machines grow
would leave every plate's meter at a different x — which reads as a rendering
fault rather than as data. The identity line went the same way: no tier the
floor still visits has room for it, so `layout.subline` is always 0 (pinned by
the verifier) and a renamed machine's identity lives in the plate's tooltip
and the node sheet. `SUBLINE_H` survives as the record of what a full-tier
floor used to reserve.

**`plateNeed` is measured against the largest body a plate can be ASKED to
draw, not the one it is drawing.** Selection promotes a plate a tier in place,
and a floor that only fitted its resting tier would collide the moment somebody
clicked.

**`PROVIDER_NODE_ID` is `__provider_bus__`, a synthetic key and never a
caption.** There is no `NodeProfile` behind the bus, but it is draggable, so it
needs a key into the same `offsets` map — namespaced so it cannot collide with
a real node id, which is a hostname. Its offset is vertical only: the box spans
the full floor width by construction, so a horizontal component would either
widen it past the floor's edge or leave the wires landing on that edge aimed at
empty space.

**A remote band's id is `remote:<served name>`, and that is the merge.** A name
several providers answer for is ONE band: the request forks at the provider box,
not before it, so the drop into it is a single run by construction.
`gateway/targets.py` merges on the same axis without the prefix: `index.targets`
is keyed by the bare served name, with one `RouteTarget` per provider under it
and target ids of the form `<provider_id>:<upstream_id>`.

**Every plate is captioned by node id or the operator's label, never by
hostname.** A worker in a `--network host` container reports the HOST's
hostname, so two containers on one Spark legitimately share one — which is the
case that made the identity line necessary in the first place.

## Failure behaviour

- **No machines at all.** `layoutCluster` returns early with `emptyMessage`
  ("No machines yet. A Spark on this network appears here on its own.") and an
  ink box equal to the viewBox. That path renders a `<p>`, not the SVG.
- **A corrupt or absent stored arrangement.** `readArrangement` returns
  `NO_ARRANGEMENT` for a parse failure, a disabled store, a wrong `VERSION` or a
  hand-edited shape, and `writeArrangement` swallows a quota error — a layout
  preference is not worth failing a render over. A NaN or out-of-range offset is
  bounded to `OFFSET_LIMIT` or dropped, so a bad value means "not moved" rather
  than a floor that cannot be drawn.
- **An offset under an id nobody answers to.** Places nothing, and the machines
  that are present draw where they always did.
- **An edge claiming `measured` with no figure.** Draws and reads exactly like
  one never probed, everywhere `edgeMeasured` is consulted.
- **No live reading for a band.** `fmt` renders the missing figure as an em
  dash, and a stale frame greys the readout and emits no out-blocks rather than
  repainting a rate that stopped arriving.
- **No launch row for an arriving deployment.** `elapsed` is null and no clock
  is drawn. No pull reporting bytes: the stepper holds at "Downloading weights"
  with no size beside it.
- **A provider logo that 404s.** Remembered for the session, and the monogram
  tile under it was drawn already.
- **`prefers-reduced-motion`.** `useParticleField` returns before starting its
  interval, so both directions of flight are suppressed together; `BandSweep`
  swaps to its still form, which is a different shape rather than the moving one
  parked at 40%.
- **A parent unmount mid-flight.** The path keeps walking off-tree for the rest
  of its span and is garbage the moment the callback stops; the `active` and
  `credits` maps are owned by the effect, so a remount starts from zero rather
  than inheriting a count for flights it can no longer see.

## Deliberately not built

**A force simulation.** At this node count physics produces drifting,
unrepeatable positions. Positions here are a pure function of the node set and
the arrangement — coordinator first, then sorted ids, dealt into a row or a grid
and a ring past twelve — because a machine you cannot learn the position of is
worse than one that is merely plain. Hand-placement is not the same thing: it is
somebody putting a machine somewhere on purpose, and it stays exactly there
until they move it again.

**Absolute stored positions.** Rejected in `order.ts` and then found to be the
wrong half of the argument: free x/y stops meaning anything across a resize or a
tier change, a displacement does not.

**Snapping, and collision refusal on drop.** A plate may be dropped on a link or
on another plate. Where somebody wants a machine drawn is not this component's
call.

**A percentage on a launch.** The runtime container fetches its own weights into
the host's cache and the control plane cannot see inside it, so no percentage
exists and none is drawn — a bar creeping at a made-up rate is read as an
estimate and planned around.

**A per-band streaming query.** `useRequestMix` queries the request archive for
one served name; asking per band would be a query per band for a hue. The
selected band paints its measured tone and every other passes null, which
renders as "no reading" rather than as a guess.

**A machine rail.** Pressing a plate lights it; the readouts live in the node
sheet a double-click opens. One detail surface, one way into it.
