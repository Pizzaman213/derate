# Feedback on "Cluster tab → typed node-graph wiring editor (revised plan)"

Read against the derate checkout on 2026-11-18. Everything below is from the code, not from memory; line numbers are current. Sections: what the tab actually is, the claims in the prompt that are wrong, what the design helps, what it hurts and how to fix each, the small corrections, and the decisions to rewrite.
## What the current floor actually is

`ui/src/tabs/ClusterTab.tsx` (not `tabs/cluster/`) composes `cluster/ClusterGraph.tsx` (1784 lines, hand-rolled SVG), `GraphToolbar`, `SelectionRail`, and the persisted arrangement from `order.ts`. `layout.ts` (2962 lines, pure) decides geometry. Reading left to right in `docs/screenshots/cluster.png`:

1. **Entry plates, one per endpoint family** (`POST /v1/chat/completions`, `/v1/audio/speech`, `/v1/audio/transcriptions`) — `endpointGroups` + `ENTRY_LABELS` (`layout.ts:154`, `:685`). README:117-121 states the reason: one plate in front of a speech band and a chat band "is a drawing of routing that does not exist".
2. **Bands, one per served name**, titled `<served> · single node · tok/s`, spanning the machines that host it. A name served locally *and* by a provider is one band (`backup` role); the provider rides on it.
3. **Provider rows** are *filtered*: `groupRemotes` (`layout.ts:546`, `SHORTLIST_MAX = 8` at `:518`) draws `backup`, `hosted` (the provider *is* a node on the roster: `connor-pi-ollama`) and `named` rows; everything else is `catalog`, counted on the grey provider bus and not drawn. An OpenRouter key with no allowlist is several hundred enabled rows.
4. **Exit plates per response content type** (`200 text/event-stream`, `audio/mpeg`, `application/json`).
5. **Machine plates** above, with memory meter, W/°C, GPU%, device; links drawn when measured, spanned, ≤4 machines, **or either end is selected** (`layout.ts:1953-1958`) — the prompt's decision 7 omits the selected-end clause.
6. **Sidebar** (not the floor) owns the routing policy: `sidebar/RoutingSection.tsx:71-75` calls `backend.setPolicy`, shows `auto_reason`, weight bars, and the `local_first` flow lamp.
7. Particles: inbound population = requests in flight (`queue_depth`/`outstanding`), outbound rate = tok/s, teal/violet by streamed ratio from `/api/history/requests` (README:234-243).

## What the graph editor helps

- **Persisting routing overrides** (1.1 store): fixes a live bug. `RoutingSection` writes `_overrides` that vanish on restart.
- **Multi-model-per-machine visibility**: today a machine serving two models shows `Audio8-TTS-Preview-0.6b +2` in the plate caption; the rows-in-a-container design is strictly better.
- **Multi-node rows with `TP n` / `rank k of n`**: the band already spans machines; rows per machine with the wire on the lowest `node_id` read the same fact without a spanning rectangle, which is what makes free x/y placement possible at all.
- **Provider alias editing by wire**: `ProviderBackupPanel.tsx:5-9` says the only way to set `aliases` was PATCH by hand; dragging `cloud → provider row` is the right gesture for it, and `ProviderService.update` already accepts `enabled_models` + `aliases`.
- **Draft model block → `POST /api/plan` verdict in place**: reuses `usePlacement`, `OverrideGate`, `Verbatim`; nothing new on the server.
- **Live "not admitting / fallback active" labels**: `RoutingConfig.flow` (`'local' | 'spilled'`) already exists and the sidebar draws it as a lamp; the wire label is the same fact at the place it happens.
- **MTP as a launch option**: `ParamBreakdown.mtp` is already measured (`resolver/params.py:36,:195`), the resolver already *subtracts* it from `weight_bytes` (`resolver.py:295-299`), and `spec_acceptance_rate` is already scraped and archived (`telemetry/engine_metrics.py`, `contracts/telemetry.py:106-113`) with nothing feeding it. The feature closes a loop the code already half-built. Scaling back up by `(total+mtp)/total` in `_plan_and_fit` is coherent with that.

## What it hurts, and the fix for each

1. **One "API Input" collapses endpoint families.** The floor's entry plates per modality exist because a TTS deployment and a chat deployment are not reachable from the same request. The prompt's single Input draws routing that does not exist — the README calls that out by name. **Fix:** one `Input` block per modality present (`endpointGroups`/`ENTRY_LABELS` logic, moved out of `layout.ts` before deletion), labelled `POST /v1/...`, and one `Output` per response content type as today. Block ids `input:<modality>`, `output:<modality>`. Column count unchanged.
2. **"One row per enabled provider model" drops the `groupRemotes` shortlist.** On this box OpenRouter with no allowlist is hundreds of enabled models (CLAUDE.md: 427 of 516 rows are provider-offered). **Fix:** keep `RemoteRole` — draw `backup`/`hosted`/`named` rows, and a collapsed `+N catalogue models` footer row that opens the `Add model` popover. Move `groupRemotes` and `SHORTLIST_MAX` to `tabs/cluster/doc.ts` rather than deleting them with `layout.ts`.
3. **`hosted` providers (a provider that is a machine, `TopologyRemote.node_id != null`) have no home.** The machine/provider split puts `connor-pi-ollama` in a cloud box. **Fix:** a hosted provider model is a row inside its machine block (socket ids `pm:` as for providers) and wires to the split's **cloud** port, since it is a `remote` target on the server. Say so in the socket rules (rule 7a's "provider row" test is `row.kind === 'provider'`, not "lives in a provider block").
4. **The rate-limit block is a third limiter layer on top of key and org `model:<served>:rpm`, with undefined precedence, no principal, and no `limit_source` string.** The prompt forbids new server design and 1.1 step 4 says "stop" if nothing is reusable — and nothing is: `LimitScope` has `KEY|ORG`, admission runs only for authenticated principals, and `_configured` filters by the principal's own limits. The honest reading of the prompt's own contingency is that the block ships hidden. **Recommendation:** drop the rate-limit block, the `limit` socket, `RoutingConfig.limits`, and the `route.set limits` op from this plan entirely (Phase 3 material alongside keys/orgs, where the per-model limits already live). Keep 1.1's persistence store. If the owner insists on enforcement: add `LimitScope.ROUTE` with `scope_id = served_name`, evaluate it in `_check_rates` after org scope for every request including unauthenticated ones, `limit_source: "route"`, and `tests/unit/test_limits.py` cases — that is a named server change, not improvisation, and it must be written into the prompt.
5. **`route.set {policy: LB_POLICY or current}` on a limits change silently converts `auto` into an override.** If the name was `auto_selected`, the op pins `local_first` and the sidebar's `auto_reason` disappears. With item 4 adopted this op has no remaining trigger; if limits survive, the op must send `policy: null` to mean "leave the override untouched", and `set_routing` must accept that.
6. **Triangle semantics: "local while any local is admitting" is `failover`, not `local_first`.** `failover` pins the first local by id and never balances two locals; `local_first` balances non-saturated locals and spills *before* admission closes. Decision 2's sentence should become "local while a local target has capacity; cloud when every local is saturated or down". The `1 · local / 2 · fallback` rank labels are correct for `local_first`; the `(sidebar)` chip triggers for the other six.
7. **Per-key/org `routing_policy` overrides bypass the split.** `openai_api.py:~634` passes `principal.key.routing_policy or principal.org.routing_policy` into `Router.select`. The split draws the name's policy, not the request's. One line of copy in the Sockets legend: "Keys and orgs may carry their own policy; this shows the name's default."
8. **Decision 9 promises "tensor parallel" for two machines; the planner decides.** Without `parallelism`, `_rank_plans` may return pipeline parallel on a slow link (SelectionRail's own text says PP below 40 GB/s). **Fix:** the block's sentence comes from the plan response (`plan.kind`, `degrees`): "one instance across spark-4d38 and spark-26af · pipeline parallel 2". Only wire `parallelism` through when the operator sets degrees explicitly (reuse `usePlacement`'s `degrees`).
9. **Deleting `layout.ts` deletes shared rules.** `runners` (6 importers), `edgeMeasured` (2), `groupRemotes`, `endpointGroups`, `TP_THRESHOLD`, `ENTRY_LABELS`. **Fix:** move `runners` to `models/rows.ts` (prompt has this), `edgeMeasured` → replace with `board.ts::linkMeasured` everywhere and delete the `SelectionRail` `TP_THRESHOLD` copy (`board.ts` gets `TP_THRESHOLD`), `groupRemotes`/`endpointGroups`/`ENTRY_LABELS` → `doc.ts`. Gate: `grep -rn "cluster/layout\|edgeMeasured\|ClusterGraph" ui/src` prints nothing.
10. **Absolute stored positions vs displacements.** `order.ts`/README:299-306 argue an absolute x/y dies on resize or tier change. That argument is about a fit-to-viewBox SVG; React Flow coordinates are viewport-independent, so absolute positions are fine — but say so in the new README, and keep `order.ts`'s `readArrangement` hygiene (version, `MAX_IDS`, NaN drop) in the new `positions.ts` instead of rewriting it. Key the record `derate.cluster.positions.<cluster_id>`.
11. **Zoom semantics change.** Today `ZOOM_MIN/MAX` are relative to the fit (every cluster rests at 100%). `minZoom 0.25 / maxZoom 2` absolute means a 16-machine graph may not fit at 0.25. **Fix:** `fitView` on mount and on `Reset view`; report the percentage relative to the fitted zoom as the toolbar does today.
12. **Particles lose the stream/batch tone.** The prompt makes responses plain teal; today the colour is historical streamed-ratio (`streamTone`, `streamBlockWidth`) and `particles.check.mjs` pins it. Either keep both channels (teal/violet by ratio, width by kind) or delete `streamingRatio`/`useRequestMix` wiring and the check cases that pin them — the prompt must say which. **Recommendation:** keep; it is already written and checked.
13. **`fixtures/wiring_rules.json` invents a cross-language fixture convention.** Nothing like it exists; `tests/fixtures/` is a Python package. If kept, place the JSON at `tests/fixtures/wiring_rules.json` next to `__init__.py`, have pytest read it with `importlib.resources`, and have `doc.check.mjs` read it by relative path with **no** `// requires:` line (hermetic — the file is in the checkout). Drop the `fixtures $NAME` env-var idea for it.
14. **Phase 1.3 puts the handler in `keys_api.py` and reuses `_refusal`.** `_refusal` only knows key/org exceptions; provider errors are mapped in `internal_api.py::patch_provider`. **Fix:** `control_plane/gateway/wiring_api.py` (new router, included above the static mount), copying `patch_provider`'s error mapping and `audit_request(... PROVIDER_UPDATED / ROUTING_CHANGED ...)`, with `ProviderService.validate_update(provider_id, patch)` added beside `update` and `update` refactored to call it first.
15. **The mockup link is unreachable to an implementer.** Delete the sentence; the prompt is complete without it only if the per-block layouts (where the split's `limit` handle sits in px, row height, container footer) are specified — add a short "Block geometry" table (block width 240, row height 28, handle offsets) or accept the implementer's choice explicitly.
